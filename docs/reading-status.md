# Statusübergänge lesen

Die Detailansicht erzeugt für Incidents eine lesende Anfrage `VALID_TRANSITIONS` mit `FACTORY=cr`, `STATUS_FACTORY=crs`, `STATUS` (aktueller Kurzcode), `PERSID=cr:<ID>`, `TENANT` (Mandantenkennung) und `TYPE=I`. Eine 32-stellige Hex-Mandantenkennung wurde beobachtet. `Get-UHDStatus -Id <ID> -Status <Code> -TenantId <Kennung>` übernimmt die explizit angegebene Kennung; ohne Angabe bleibt `TENANT` für bestehende Aufrufe weg. Ob der Server die Anfrage ohne dieses Feld akzeptiert, ist nicht belegt. Keine Kennung ableiten oder ersatzweise setzen.

Die Statusantwort ist ein mit `@` getrennter Text: Standardcode, Standardbezeichnung (beide leer, wenn keiner gewählt ist), ein nicht ausgewertetes Feld und anschließend Paare aus Zielcode und Kommentarflag. Die Paare behalten ihre Reihenfolge. `IsDefault` kennzeichnet den Standard; nur für ihn liefert diese Antwort eine `Label`. `CommentRequired` bildet das beobachtete Flag ab: `N` ist falsch, `Y` bedeutet laut Browserauswertung wahr. Das dritte Feld der Kopfzeile wird nicht ausgewertet.

Die Textwerte können URL-kodiert sein. Im beobachteten Format folgt nach den Paaren ein abschließendes `@`, gefolgt von CRLF und einem NUL-Zeichen. Das Modul akzeptiert weiterhin seine bisher unterstützte Kurzform aus `CODE@Bezeichnung`; sie sagt nichts darüber aus, ob es sich um den Standard handelt oder ein Kommentar erforderlich ist. Unvollständige oder widersprüchliche Antworten werden ohne Teilausgabe abgelehnt. Das tatsächlich leere Antwortformat ist offen. Es werden keine Statusänderungen durchgeführt.
